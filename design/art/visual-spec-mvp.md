### 0.4 技术美术约定（Graphics → generateTexture，必读）

这四条不遵守会产生边缘裁切与内存泄漏，工程侧请照做：

1. **描边内缩**：Phaser `Graphics` 的 `lineStyle` 是**居中描边**。绘制带描边的矩形时，必须向内缩进 `lineWidth / 2`，否则描边外半圈会被纹理边界裁掉。
   ```ts
   // 正确：目标 240×100、描边 4 的卡片
   g.fillStyle(CARD_FILL, 1);
   g.fillRoundedRect(2, 2, 236, 96, 16);
   g.lineStyle(4, CARD_STROKE, 1);
   g.strokeRoundedRect(2, 2, 236, 96, 16);
   g.generateTexture('tex_card_answer', 240, 100);
   ```
2. **圆形/多边形同理**：半径需减去 `lineWidth / 2`。例：目标直径 44、描边 4 → `fillCircle(22, 22, 20)` + `strokeCircle(22, 22, 20)`，纹理尺寸 `44 × 44`。
3. **生成后销毁 Graphics**：`g.generateTexture(key, w, h); g.destroy();` —— 不 destroy 会持续占用显示列表与内存。
4. **全部在 BootScene 一次性生成**，后续场景只从 `TextureManager` 取，不在运行时重复生成。纹理尺寸取偶数即可（Phaser 3 WebGL 支持 NPOT，无需强制 2 的幂）。

## 1. 视觉身份（精简版美术圣经）

### 1.1 三个关键词

**「清晰 · 跃动 · 干净」**

- **清晰（Clarity）**：一切视觉决策服务于「玩家一眼看懂发生了什么」。信息层级只有三层，没有第四层。颜色不为装饰服务，只为区分与反馈服务。
- **跃动（Bounce）**：几何形态带弹性，动效回弹有 overshoot，让答对/击杀有「手感」。但跃动体现在**缓动曲线**上，不体现在粒子数量上。
- **干净（Clean）**：纯色块 + 等宽描边，无渐变堆叠、无材质、无阴影、无噪点。屏幕永远留白（暗底）多于实体。

### 1.2 情绪基调

冷静的深蓝底子上，几团高饱和的暖色在快速运动。像一块深色黑板上有几支荧光笔在划动——**理性底色 + 情绪高光**。
紧张感来自「时间与移动」，不来自「画面复杂度」。玩家焦虑时画面反而更空。

### 1.3 参考方向（文字描述，禁止作为素材下载依据）

- **几何语言**：扁平化矢量图标风（Flat Vector Icon），2–4px 等宽描边，纯色填充，圆角矩形卡片。
- **构图**：居中对称 + 单一视觉焦点。任何一屏只有一个「主角元素」。
- **动效质感**：Material / iOS 的弹性缓动观感（Back / Cubic 曲线），而非卡通夸张的挤压拉伸（Squash & Stretch）。**不做**夸张形变。
- **反面清单（禁止出现）**：拟物质感、金属渐变、外发光堆砌、扫描线、赛博朋克霓虹、像素风、手绘涂鸦风。

### 1.4 三条不可协商的红线

1. **答题公平红线**（详见 §5）——视觉上正确答案与干扰项无任何可察觉差异。
2. **零素材红线**——不引入任何需要下载/打包的图片、音频、字体文件。
3. **性能红线**（GDD 1.2）——同屏 tween 并发 ≤ 40，同屏特效 Sprite ≤ 24，**MVP 全程不使用 `Phaser.GameObjects.Particles.ParticleEmitter`**，不使用任何后处理管线（Blur / Glow / Bloom）。

### 2.3 色觉障碍处理（三通道冗余）

色觉障碍（红绿色盲约占男性 8%）下，纯颜色区分会失效。以下所有语义必须**颜色 + 形状 + 文字**三重编码：

| 语义 | 通道①颜色 | 通道②形状 | 通道③文字 |
|---|---|---|---|
| 答对 | `CORRECT` 绿 | **圆形**徽章 + ✓ 折线 | 文案「答对了」 |
| 答错 | `WRONG` 红 | **菱形**徽章 + ✗ 交叉线 | 文案「答错了」+ 显示正确答案 |
| 普通小怪 | `MOB_GRUNT_FILL` 橙 | **圆形** | — |
| 快速小怪 | `MOB_RUNNER_FILL` 琥珀 | **正三角形** | — |
| 厚血小怪 | `MOB_TANK_FILL` 紫 | **正六边形** | — |
| 倒计时 ≤5s | 转 `ACCENT` | 数字放大 1.15× | 数字本身 |
| 倒计时 ≤3s | 转 `WRONG` | 数字放大 1.15× + 抖动 | 数字本身 |

**关键设计**：`CORRECT`(L=0.491) 与 `WRONG`(L=0.293) 的**相对亮度比 1.58:1**，在完全色盲（全色盲）下仍能靠明暗区分。这是刻意的，不要替换为两个亮度接近的绿/红。

**禁止**：任何「仅靠颜色区分」的信息表达。禁止用红/绿单独表示状态。

### 3.3 答案轨道几何（答题场景核心）

> 这是答题场景唯一需要精确计算的几何关系，工程侧请严格按此实现。

#### 3.3.0 实现偏差警示（v1.1 增补，优先级高于下文 3.3）

v1.0 的 §3.3 按「1280 × 720 + 水平 marquee 轨道」书写，但工程侧（`src/main.ts` / `public/config/questionConfig.json`）实际实现为 **960 × 640 + 椭圆轨道**。三项偏差**全部以实现侧为准**，文档此处为追认修订：

| 项 | v1.0 文档值 | 实现实际值 | 处置 |
|---|---|---|---|
| 逻辑分辨率 | `1280 × 720` | **`960 × 640`** | **以实现为准**。本文档所有绝对坐标需乘以 `x: ×0.75` / `y: ×0.889` 换算；v1.1 新增条目一律直接给 `960 × 640` 值 |
| 轨道形态 | 水平循环平移，步长 `264` | **`movementType: "circular"` 椭圆**（`trackRadiusX 230` / `trackRadiusY 125`） | **以实现为准**。§3.3 的「步长 264」段落作废 |

#### 3.3.1 实测几何（960 × 640，权威值，工程侧照此核对）

```
椭圆轨道：中心 (480, 435)，trackRadiusX 230，trackRadiusY 125
判定区（光门）：260 × 100，中心 = 椭圆最低点 (480, 560)，即 y ∈ [510, 610]、x ∈ [350, 610]
卡片：200 × 76，4 张，相位均布，间隔 90°
卡片中心：(480 + 230·cosθ, 435 + 125·sinθ)
判定区 Y 由 AnswerTrack.zoneY 给出：circular 时 = centerY + radiusY = 560
```

**判定窗口（令 φ = 卡片相位相对椭圆最低点的偏角，`src/systems/AnswerTrack.ts` 的 `overlapRatioOf()` 即为轴对齐矩形交集）**

| 判定 | 相位窗口 | 换算公式 |
|---|---|---|
| `ratio ≥ 0.5`（明确命中） | `|φ| ≤ 31.6°`，共 `63.2°` | `overlapW = min(200, 230·(1 − |sinφ|))`；`overlapH = min(76, 125·cosφ − 37)`；`ratio = overlapW × overlapH / 15200` |
| `0.3 ≤ ratio < 0.5`（模糊命中） | `31.6° < |φ| ≤ 40.8°`，双侧共 `18.4°` | 同上 |
| `ratio < 0.3`（未命中） | `|φ| > 40.8°` | 同上 |
| 峰值 | `φ = 0` 时 `ratio = 1.0`（卡片完整落在光门内） | — |

**唯一性结论（优于 v1.0 水平轨道方案）**：有效命中窗口 `81.6°` **< 卡片相位间隔 `90°`**，因此**任意时刻至多 1 张卡片 `ratio ≥ 0.3`**，判定零歧义，无需「取 max」兜底。
（对比：v1.0 水平轨道方案下 `ratio ≥ 0.3` 窗口 `356px` **>** 步长 `264`，会出现 2 张卡片同时 `≥ 0.3`，需依赖取 max。椭圆方案反而更干净。）

**明确命中时间窗口（椭圆周长 ≈ 1140 px，Ramanujan 近似）**

| 速度 | 走完一圈 | 明确命中窗口 | 有效命中窗口 | 评估 |
|---|---|---|---|---|
| `200 px/s`（`minSpeedLimit`） | `5.70s` | `1000ms` | `1293ms` | ✅ 宽松 |
| `800 px/s`（`baseSpeed`，当前 Lv.1 值） | `1.42s` | **`250ms`** | `322ms` | ⚠️ 偏紧 |
| `1200 px/s`（`maxSpeedLimit`） | `0.95s` | **`167ms`** | `215ms` | ❌ 过紧 |

> **定稿结论**：卡片 `200×76` + 判定区 `260×100` 的组合**几何上完全成立，不需修改尺寸**。
> **不要**把判定区加宽到 `300`：那会使有效窗口达 `87.6°`，逼近 `90°` 相位间隔，唯一性余量只剩 `2.4°`，风险过高。
> 压力来自**速度而非尺寸**。美术侧建议（**属 GDD 数值，需策划确认后由工程改 `questionConfig.json`，不改代码**）：`baseSpeed` `800 → 520`（明确窗口 `385ms`）、`maxSpeedLimit` `1200 → 700`（明确窗口 `286ms`）。

#### 3.3.2 v1.0 原设计基准（已作废，仅存档）

```
轨道：水平循环平移（marquee），全部 4 张卡片同时可见
┌────────────────────────────────────────────────────────────┐
│                                                            │
│   卡片宽 240  ──┤  间距 24  ├─   步长 step = 264           │
│   循环周期总宽 = 4 × 264 = 1056                             │
│   轨道可视宽 = 1280（x: 0 → 1280）                          │
│   判定区中心 x = 640，宽 260 → x ∈ [510, 770]               │
│                                                            │
│   ∵ step(264) > 判定区宽(260)                               │
│   ∴ 任意时刻至多 1 张卡片与判定区有显著重叠                  │
└────────────────────────────────────────────────────────────┘
```

**判定规则（对齐 GDD `overlapThreshold: 0.3` / `stopThreshold: 0.5`）**

```
overlapRatio = (卡片与判定区的相交矩形面积) / (卡片面积)     // 卡片面积 = 240 × 100
```

| 条件 | 结果 |
|---|---|
| `maxOverlapRatio >= 0.5`（`stopThreshold`） | **明确命中**：该卡片被选中，进入判定流程 |
| `0.3 <= maxOverlapRatio < 0.5`（`overlapThreshold`） | **模糊命中**：仍判定为该卡片，但动效走「命中」的弱化版（判定区边框闪 1 次而非 2 次） |
| `maxOverlapRatio < 0.3` | **未命中**：不选中任何卡片，不扣题数、不扣时间，播 §4.2 未命中动效，`1200ms` 后恢复移动 |

> **为什么用「水平轨道 + 全局停止按钮」而不是直接点移动的卡片**：GDD 2.2 已识别风险「玩家明明知道正确答案但点不中移动目标，会把失败归因于操作而非知识」。固定大按钮（320×96，静止，永不移动）把执行难度降到最低，玩家考核的是「知识 + 时机」而非「手指精度」。这是本规格最重要的可玩性决策。

## 5. 答题公平红线（GDD 1.3 的视觉强制约束）

> **这一节是红线，任何一条被违反即视为美术规格未通过。**

### 5.1 强制一致项

同一题内，所有答案卡片的以下属性**必须完全一致**，且必须**由同一份样式常量对象驱动**（代码中只能有一处定义）：

| # | 属性 | 强制值 |
|---|---|---|
| 1 | 尺寸 | `240 × 100` |
| 2 | 圆角半径 | `16` |
| 3 | 填充色 | `CARD_FILL` `#25365C` |
| 4 | 描边色 | `CARD_STROKE` `#4A6BB0` |
| 5 | 描边宽度 | `4` |
| 6 | 文字颜色 | `CARD_TEXT` `#F2F6FF` |
| 7 | 文字字号 | `28`（且所有卡片使用同一个自动缩放结果） |
| 8 | 文字字体 / 字重 / 对齐 | 完全一致，居中对齐 |
| 9 | 不透明度 `alpha` | `1.0` |
| 10 | 是否存在阴影 / 发光 | **均不存在** |
| 11 | 深度 `depth` | 完全相同（同层） |
| 12 | 移动速度 | 同一 `answerSpeed` 值 |
| 13 | 移动轨迹 | 同一水平轨道，同一相位公式 |
| 14 | 移动缓动 | `Linear`（GDD `movementEasing: linear`） |
| 15 | 旋转角度 | 均为 `0`，**卡片不得旋转** |
| 16 | 缩放 `scale` | 均为 `1.0`（判定完成后才允许差异化） |
| 17 | 进入 / 退场动画 | 完全一致 |

### 5.2 明令禁止项

1. **禁止**为正确答案添加任何视觉标记：更亮的描边、更粗的边框、发光、脉动、更大字号、图标、更靠前的 `depth`。
2. **禁止**让正确答案的运动更平缓 / 速度更慢 / 停留在判定区的时长更长 / 出现在判定区的频率更高。
3. **禁止**在判定结果揭晓前（玩家按下停止 → 系统完成判定之前）让任何卡片呈现差异化样式。
4. **禁止**固定正确答案的位置序号（A/B/C/D）。**每道题的选项顺序必须随机化**，且正确项在四个位置上的长期分布需均匀。
5. **禁止**用卡片背景色 / 边框色的任何数值差异编码正确性（包括「肉眼几乎看不出」的微小差异）。

### 5.3 代码级强制检查点

工程实现必须满足：

- `AnswerCardView`（或等价的卡片视图类）的构造函数与 `setStyle()` **不得接收 `isCorrect` 参数**。正确性的唯一来源是 `OptionData.id === QuestionData.correctId`，且**只在判定时读取一次**。
- 卡片样式从单一常量对象读取：
  ```ts
  const ANSWER_CARD_STYLE = Object.freeze({ w: 240, h: 100, ... });
  ```
  `Object.freeze` 防止运行时被意外改写。
- 纹理层面只生成**一个**卡片纹理 `tex_card_answer`。**不存在** `tex_card_answer_correct` 这类变体纹理。判定后的绿/红变化一律用 `setTint()` 实现，不换纹理。

## 6. 可访问性清单（Basic 级）

> 分级：**Basic**。定义 = 覆盖触摸目标、对比度、色觉障碍、动效减弱、字号下限五项基线要求。**不含**：完整键盘导航、屏幕阅读器 ARIA 树、字幕系统、输入全键位重映射（这些属 Standard / Comprehensive 级，MVP 不做）。

### 6.1 触摸目标尺寸

| 要求 | 值 |
|---|---|
| **最小可点击区域** | **`88 × 88`**（设计分辨率 px，≥ WCAG 44×44 CSS px 的 2 倍） |
| 相邻可点击元素最小间距 | `24` |
| 主按钮实际尺寸 | `240 × 72` → 高度 `72` **不达标**，需扩大点击区 |

> ⚠️ **修正**：主按钮 `240 × 72` 高度 `72 < 88`，**不满足最小触摸目标**。处理方式二选一，工程侧采用 **A 方案**：
>
> **A（推荐）**：视觉尺寸保持 `240 × 72`，通过 `setInteractive()` 传入扩大的 `HitArea` 矩形 `240 × 88`（垂直方向上下各外扩 `8`），视觉不变、命中区达标。
> ```ts
> btn.setInteractive(new Phaser.Geom.Rectangle(0, -8, 240, 88), Phaser.Geom.Rectangle.Contains);
> ```
> **B**：按钮视觉尺寸改为 `240 × 88`。
>
> 停止按钮 `320 × 96`、答案卡片 `240 × 100`、判定区 `260 × 120`、结算面板按钮 `240 × 88`（采用 B 方案）均已达标，无需放大。

### 6.2 对比度

| 场景 | 最低要求 | 本规格最低实际值 |
|---|---|---|
| 正文文字（< 24px） | `4.5 : 1` | `5.31 : 1`（主色按钮白字） |
| 大号文字（≥ 24px，或 ≥ 18.66px 粗体） | `3 : 1` | `7.37 : 1`（`TEXT_SECONDARY`） |
| 图形 / UI 组件边界 | `3 : 1` | `4.28 : 1`（`MOB_TANK_FILL` on ground） |

完整逐项校验见 §2.2。**所有有效项均达标。**

### 6.3 色觉障碍

已在 §2.3 给出三通道冗余方案。强制执行要点：

- 正确 / 错误：**颜色 + 形状（圆✓ / 菱形✗）+ 文字** 三重编码。
- 小怪类型：**形状为主**（圆 / 三角 / 六边形），颜色为辅。
- 倒计时告警：**颜色 + 尺寸变化 + 数字本身** 三重编码。
- 禁止任何「仅靠颜色区分」的信息表达。

### 6.4 动效减弱开关（Reduce Motion）

- **入口**：主菜单右下角 `tex_icon_sound_*` 同排，放一个 `40 × 40` 图标 + `22px` 文字标签「减弱动效」。
- **默认值**：`false`（关闭 = 完整动效）。
- **持久化**：`localStorage['kb_mow_reduce_motion'] = '0' | '1'`。

**开启后的降级规则**：

| 动效类别 | 降级处理 |
|---|---|
| 缩放 / 位移 / 抖动 tween | **时长置 0**，直接 `setScale` / `setPosition` 到终态 |
| 击退位移 | 取消 |
| 屏幕震动（§4.13） | **完全取消** |
| 连击弹跳、升级 `fx_ring`、答对 `fx_spark` | **完全取消** |
| 颜色变化 | **保留**，但时长 × `0.5` |
| `alpha` 渐变 | **保留**，但时长 × `0.5` |
| 场景切换遮罩 | 保留，`alpha` 时长 × `0.5` |
| 全屏 `SCRIM` 遮罩 | 保留（不可跳过，否则弹窗内容不可读） |

**实现约定**：所有 tween 统一走一个包装函数，工程侧照此实现：

```ts
function fx(tweenCfg: Phaser.Types.Tweens.TweenBuilderConfig): Phaser.Tweens.Tween {
  if (MotionPref.reduceMotion) {
    if (tweenCfg.duration !== undefined) tweenCfg.duration = 0;
    if (tweenCfg.alpha !== undefined && typeof tweenCfg.alpha === 'number') {
      tweenCfg.duration = (tweenCfg.duration as number) * 0.5;  // alpha 保留半速
    }
    tweenCfg.ease = 'Linear';
  }
  return scene.tweens.add(tweenCfg);
}
```

## 7. 字体方案

### 7.1 主字体栈（系统字体，零文件依赖）

Phaser `Text` 的 `fontFamily` 字符串，工程直接复制：

```
"-apple-system","BlinkMacSystemFont","Segoe UI","PingFang SC","Hiragino Sans GB","Microsoft YaHei","微软雅黑","Source Han Sans SC","Noto Sans CJK SC","WenQuanYi Micro Hei","Helvetica Neue",Helvetica,Arial,sans-serif
```

**回退链说明**：

| 顺序 | 字体 | 覆盖平台 |
|---|---|---|
| 1–2 | `-apple-system` / `BlinkMacSystemFont` | iOS / macOS Safari & Chrome |
| 3 | `Segoe UI` | Windows 英文 |
| 4 | `PingFang SC` | macOS / iOS 中文（首选中文） |
| 5 | `Hiragino Sans GB` | macOS 旧版中文回退 |
| 6–7 | `Microsoft YaHei` / `微软雅黑` | Windows 中文（**必须两个都写**，部分环境只认中文名） |
| 8–9 | `Source Han Sans SC` / `Noto Sans CJK SC` | Linux / Android 中文 |
| 10 | `WenQuanYi Micro Hei` | Linux 深度回退 |
| 11–13 | `Helvetica Neue` / `Helvetica` / `Arial` | 通用拉丁回退 |
| 14 | `sans-serif` | 最终兜底 |

> **引号规则**：含空格的字体名必须加引号，否则 Phaser 传给 canvas 时会解析失败。`微软雅黑` 同样加引号。

### 7.2 等宽数字字体栈（HUD 动态数值专用）

```
"SF Mono","SFMono-Regular","Segoe UI Mono","Roboto Mono",Menlo,Consolas,"Liberation Mono","Courier New",monospace
```

**使用范围**：倒计时秒数、连击数、击杀数、经验值、伤害数字。

> 这些字体不含中文字形，但 HUD 数值全为阿拉伯数字，无中英文混排问题。若某平台全部缺失，回退 `monospace` 仍保证等宽。

### 7.3 Phaser 用法约定

```ts
// 常量（工程复制到 src/config/theme.ts）
export const FONT_SANS =
  '"-apple-system","BlinkMacSystemFont","Segoe UI","PingFang SC","Hiragino Sans GB","Microsoft YaHei","微软雅黑","Source Han Sans SC","Noto Sans CJK SC","WenQuanYi Micro Hei","Helvetica Neue",Helvetica,Arial,sans-serif';

export const FONT_MONO =
  '"SF Mono","SFMono-Regular","Segoe UI Mono","Roboto Mono",Menlo,Consolas,"Liberation Mono","Courier New",monospace';

// 使用
this.add.text(x, y, '题目', {
  fontFamily: FONT_SANS,
  fontSize: '32px',
  fontStyle: '500',
  color: '#F5F8FF',
  align: 'center',
  wordWrap: { width: 1120 },
});
```

**三条强制约定**：

1. **禁止 `fontStyle: 'bold'` + 中文**：多数系统中文字体无独立 Bold 字形，浏览器会做**合成加粗**，导致笔画粘连、小字号下糊成一团。中文标题改用**字号提升**（如 `40` 而非 `32+bold`）或 `fontStyle: '500'`/`'600'`（仅在有 Medium/Semibold 字形的平台生效，无则回退 normal，不会合成加粗）。
2. **`fontSize` 必须带单位**：写 `'28px'`，不写 `28`。
3. **不使用 `resolution` 缩放**：Phaser `Text.resolution` 默认取 `devicePixelRatio`，在移动端会导致纹理内存翻倍。设 `resolution: 1`，由 Scale.FIT 统一处理清晰度。

#### 8.2.1 手动走位输入映射（决策 2 定稿）

| 输入 | 平台 | 行为 |
|---|---|---|
| `W` / `A` / `S` / `D` | 桌面端 | 8 向移动，**斜向向量归一化**后乘速度，斜向不加速 |
| `↑` / `↓` / `←` / `→` | 桌面端 | 同上，与 WASD 等价 |
| 按住屏幕 / 按住鼠标 | 全平台 | 玩家**持续朝触点方向**移动；**松开即停**（速度归零，无惯性滑行） |
| 无输入 | 全平台 | 玩家静止 |

**硬性约束**

- **不做虚拟摇杆**：禁止出现摇杆基座、摇杆头、方向键图形等任何常驻控件。屏幕即摇杆，触点即方向。
- **攻击仍然全自动**：移动**只影响走位**，不影响攻击频率、攻击方向、攻击目标选择。自动攻击的目标选择逻辑（最近小怪）保持不变。
- 玩家被限制在战场区内（`x ∈ [22, GAME_WIDTH − 22]`、`y ∈ [战场上边 + 22, 战场下边 − 22]`，`22` = 玩家半径），越界钳制，不做反弹。
- 触屏与键盘**可同时生效**，取两者向量的归一化合成；若都为 `0` 则静止。

#### 8.2.2 攻击范围环半径 `140` 评估（决策 2 第 6 项）

**结论：`140` 够用，保持不变。**

| 判据 | 计算 | 结论 |
|---|---|---|
| 覆盖占比（`960×640`，战场区 `960 × 506`） | `π × 140² ÷ (960 × 506) = 61575 ÷ 485760 = 12.7%` | ✅ 基准态覆盖约 1/8 战场，站位决策有意义 |
| 满加成态（半径 `320`） | `π × 320² ÷ 485760 = 321699 ÷ 485760 = 66.2%` | ✅ 覆盖近 2/3 战场，成长感明显 |
| 预警距离 | 玩家出生点 `(480, 320)` 到最近战场边（上边 `y 64`）距离 `256px`；到左右边 `480px`。均 `> 140` | ✅ 小怪从边界外 `40px` 进入，进入攻击范围前有足够反应距离 |
| 小怪尺寸参照 | 最大小怪（厚血，外接半径 `20`）+ 玩家半径 `22` = `42`，远小于 `140` | ✅ 环内有足够空间容纳多只怪，可读性好 |

**同时补两项可读性强化（不改 `140` 本身）**

1. **环 alpha 提高**：`ALPHA.PLAYER_RANGE` `0.18 → 0.22`。手动走位下玩家会主动盯环做距离判断，`0.18` 在 `BG_ARENA` `#111A2E` 上偏淡。
2. **新增半程刻度环**：在半径 = `当前 range × 0.5` 处画一圈虚线环，`8` 段等分虚线，线宽 `2`，颜色 `PLAYER_RANGE` `#2BD9C4`，alpha `0.12`。作用是给玩家一个「半程」参照，判断小怪还有多远进圈。纹理 `tex_player_range_tick`，尺寸 `640 × 640`（= 最大范围直径），运行期 `scale` 缩放到当前 range。

> **不做**环内填充加深、**不做**环外危险区染色——两者都会显著加重视觉负载，违反 §1.2「屏幕永远留白（暗底）多于实体」。

#### 8.2.3 触屏拖动方向指示器（决策 2 第 5 项定稿）

**形态：玩家脚下到触点的淡色引线 + 触点端小圆环。** 不在玩家身上加箭头（`44px` 的圆上叠箭头太碎，且与已有的内部朝向三角打架）。

| 项 | 值 |
|---|---|
| 实现载体 | **引线**：一个常驻 `Graphics` 对象（`scene.add.graphics().setDepth(45)`），每帧 `clear()` 后 `lineStyle(4, PLAYER_TRAIL, 0.45)` + `lineBetween()` 重画，**不** `generateTexture()`（长度与方向每帧变化，生成纹理反而浪费）。**触点圆环**：一个常驻 `Image`（`tex_ui_drag_dot`，`20×20`），`setPosition()` 跟随触点，便于对整组做 alpha tween |
| 引线起点 | 玩家中心（随玩家移动） |
| 引线终点 | 沿移动方向，长度 = `min(触点与玩家中心的距离, 160)` |
| 引线线宽 | `4` |
| 引线颜色 | `PLAYER_TRAIL` `#2BD9C4`（= `PLAYER_FILL`，不新增色） |
| 引线 alpha | `0.45` |
| 触点圆环半径 | `10`，线宽 `4`，同色 `PLAYER_TRAIL`，alpha `0.6` |
| 长度上限 | **`160`**（= 攻击范围环基准 `140` + `20`，让「引线满长」与「小怪刚好在环外」视觉对齐） |
| 最小显示长度 | **`24`**。触点距玩家中心 `< 24` 时**不绘制引线**（避免手指微抖导致引线抖动） |
| 移动死区 | **`16`**。触点距玩家中心 `< 16` 时玩家不移动（防抖），此时引线不显示 |
| `depth` | **`45`**（玩家层 `40` 之上、技能层 `50` 之下；见 §0.2） |
| 出现时机 | `pointerdown` 落在战场区内 → `alpha 0 → 0.45` |
| 出现动效 | `100ms`，`Quad.easeOut` |
| 消失时机 | `pointerup` / `pointercancel` / 指针移出战场区 → `alpha 0.45 → 0` |
| 消失动效 | `120ms`，`Quad.easeIn`，动画结束后 `clear()` |
| 键盘输入时 | **不显示**。指示器只在指针拖动时出现，键盘走位无需指示（玩家本体就在动） |
| 减弱动效开关 | **保留显示**（这是功能性信息，不是装饰），但 `alpha` 渐变时长 × `0.5`（`100 → 50ms` / `120 → 60ms`），且引线长度不做弹性插值，直接置终态 |

**tween 成本**：单次出现/消失各 `1` 个 tween，同时最多 `1` 个指示器 → 峰值 `1`，可忽略。指示器本体不占 `fx_ring` / `fx_spark` 对象池名额。

#### 8.2.4 玩家移动朝向反馈（决策 2 第 7 项）

**结论：要「朝向指示」，不要「拖尾」。**

| 元素 | 处理 | 说明 |
|---|---|---|
| **玩家内部朝向三角**（§3.1 已定义，`PLAYER_CORE` `#EAFFFB`） | **保留并启用旋转**：三角指向 = **当前移动方向**（不是攻击方向）。转向用最短角差插值，`120ms`，`Quad.easeOut` | 该元素**已存在于 v1.0 规格**，无需新增纹理，只需补一句绑定语义 |
| **玩家静止时** | 三角**不隐藏**，保持最后朝向，`alpha 1.0 → 0.7`，`120ms`，`Linear` | 静止时三角突然消失会被玩家误判为 bug |
| **玩家拖影**（`tex_player_trail`，`24px`，alpha `0.25`） | **手动走位下停用**。纹理仍在 BootScene 生成（零额外成本，保留给后续可能的自动漂移模式），但 GrassScene **不创建拖影实例** | 手动走位会频繁启停、急转向，拖尾会留下大量短促残留，视觉噪点高，且吃掉对象池名额 |

### B-1 【已定稿】答题选中方式 = 两种都支持（最大容错）

**拍板值**：路径 A（停止按钮 / 空白区域 / 空格）与路径 B（直接点中移动的卡片）**并存**。

| 子项 | 结论 | 落点 |

### C-1 需要工程侧立即修正的一项

| # | 问题 | 处置 |

| C-1-1 | **emoji 字形（🗡 / 🔫 / 💥）违反零素材红线**（§1.4）。emoji 由系统字体渲染，**不同平台字形、配色、描边完全不同**（Windows 是 Segoe UI Emoji 彩色版，macOS 是 Apple Color Emoji，部分 Linux 直接豆腐块），且**不可 tint**、不可控色，无法纳入配色系统与对比度校验 | **必须替换为 Graphics 程序化图标**。三个武器图标直接复用已生成的武器剪影纹理（`weapon-blade` / `weapon-smg` / `weapon-scatter`）缩放到 `32 × 32` 置入格子，与场上武器造型一致，还省一套图。若格子内需要更强识别度，用 §3.1 形态字典风格画 `24 × 24` 的纯色剪影（大刀=斜置长条+三角尖；机关枪=矩形机匣+短枪管；霰弹枪=矩形+双平行管），`2px` 等宽描边 |
