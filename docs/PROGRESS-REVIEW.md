## 五、GDD 三条硬红线合规审计（含实测量化）

> GDD 第一部分明确定义了必须 100% 遵守的法则。审计方式：逐行扫描 + 按配置实算数值。以下三条**全部违规**，其中红线 2 / 红线 3 已由我本人二次复核确认。

### 🔴 红线 2｜核心绑定唯一性 —— **违规（最严重）**

**GDD 1.3 原文**：答题质量（正确率、答题速度）必须是决定割草爽感的**唯一且核心因素**。

主链路本身是合规的：`QuizEngine → QuizResult → computeGrassCuttingBonus`（三项乘数）→ `resolveWeapons → WeaponSystem(只读) → CombatSystem`。问题出在**两条旁路**：

**旁路 A（已复核确认）—— 击杀连击独立提供最高 3× 伤害**

```
src/systems/ComboSystem.ts:78-88   damageMultiplier = 1 + comboDamageGrowth × (count-1)，上限 comboMaxDamageMultiplier
src/systems/ComboSystem.ts:83      下限写死为 1（意味着它永远不会削弱，只会增强）
grassCuttingConfig.json            comboDamageGrowth: 0.1，comboMaxDamageMultiplier: 3
src/scenes/GrassCuttingScene.ts:623 近战：sweepSector({ ..., comboMultiplier: this.combo.damageMultiplier })
src/scenes/GrassCuttingScene.ts:704 远程：applyHit({ ..., comboMultiplier: this.combo.damageMultiplier })
```

这里的 `combo` 是**击杀连击**（在 `comboTimeWindow: 2` 秒内连续击杀），**与答题质量完全无关**。连杀 21 只怪即可拿满 3×，且这是正反馈雪球：打得快 → 连击高 → 伤害高 → 打得更快。

**实测量化：伤害倍率 = 答题加成 × 连击加成**（学科系数取 math=1，level=1）

| 玩家表现 | 答题加成 | 连击加成 | 实际伤害倍率 |
|---|---|---|---|
| 全对 + 极速 + 连对10 | 3.00（顶到上限） | 1.0 | **3.00** |
| 半对 + 中速 + 无连对 | 1.00 | 1.0 | **1.00** |
| **全错 + 超时 + 连杀21** | 0.60（触发保底） | **3.0** | **1.80** |

**结论：一个全部答错的孩子，只要手速快，打出的伤害（1.80×）比一个答对一半的孩子（1.00×）高出 80%。** 这直接推翻了「答题质量是唯一核心因素」的设计基石。

**旁路 B（可疑）—— 击杀经验推高等级，等级再转化为伤害**

```
rewardConfig.scoreSettings   expPerKill: 2，expPerCorrectAnswer: 5
```

### 🔴 P0-0A　斩断「击杀连击 → 伤害」旁路（红线 2-A）

- **现状**：`comboDamageGrowth: 0.1` + `comboMaxDamageMultiplier: 3`，使击杀连击可独立于答题提供最高 **3× 伤害**。实测全错+满连击的孩子（1.80×）伤害**高于**答对一半的孩子（1.00×）达 80%。
- **偏差原因**：ComboSystem 最初是作为「打击感反馈」引入的（连击数飘字很爽），但 `damageMultiplier` 被接进了真实伤害结算，从视觉反馈越权成了战力来源。T-020 做结算透明化时也只展示了答题三项乘数，没把连击这一项纳入审视。
- **建议行动**（成本极低，改配置即可验证）：
  1. **首选方案**：把 `comboDamageGrowth` 改为 `0`，连击**只保留得分加成与视觉反馈**（`comboSkillDurationGrowth` 也建议一并归零或大幅下调），彻底回归「答题是唯一战力来源」。
  2. **折中方案**（若你舍不得连击的手感）：保留连击但**把上限压到 1.3× 以内**，并让它乘在答题加成**之后**而非并列——即 `最终伤害 = 答题加成 × (1 + 连击 × 0.01)`，让答题仍是主导项。
  3. 无论选哪个，**都要重新验算**：满连击+全错的伤害必须 < 无连击+全对的伤害，否则核心绑定依然不成立。

### 🔴 P0-0B　补上动态难度下调，堵住死亡螺旋（红线 3）

- **现状**：`setProgress(elapsed / totalTime)` 是**唯一**的难度输入，纯时间驱动，零玩家表现因子。全项目 `dda` / `动态难度` / `assist` 关键词零命中。
- **偏差原因**：GDD 1.3 的软失败保护原则在落地时被**简化成了「伤害保底 floor」**——只保了分子，忘了分母。而 GDD 原文要求的是「动态难度降低机制」，两者不是一回事。这个简化从 MVP 第一版沿用至今，20 关扩展、Boss 关、答错暂停等后续迭代都没回头补它。
- **建议行动**（这是**对儿童玩家伤害最大**的一项，建议优先于所有内容/美术工作）：
