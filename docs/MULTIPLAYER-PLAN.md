# 局域网多人游戏模式 · 设计方案（T-032，只规划暂不实施）

> 需求来源：小朋友试玩反馈「加入局域网多人游戏模式」。本文档是**实施前方案**，
> 未写任何代码；立项前需主理人拍板模式取舍与依赖引入。

## 一、目标与约束

- **场景**：同一局域网（家里 Wi-Fi）下 2~4 台设备（手机/PC 浏览器）联机游玩，无需公网。
- **既有约束**：
  - 项目当前「零 npm 依赖」红线 → 联机需要网络层，**必须引入新依赖并经人工确认**；
  - 零素材红线不受影响；GDD 数据驱动、配置校验、无头验证门禁全部沿用；
  - 单机模式必须始终可用（联机是增量，不是改造）。

## 二、模式取舍（建议先做「合作割草」）

| 模式 | 玩法 | 核心绑定（GDD 1.3）如何保留 | 复杂度 |
|---|---|---|---|
| **A. 合作割草（推荐首发）** | 2~4 人同进同一关的**同一张世界**，各自操控角色一起割怪；Boss 血量按人数放大 | 每人各自答题 → 自己的伤害加成；团队伤害 = 各人答题质量的和——答题差的人就是「混子」，社交压力自然形成 | 中 |
| B. 传送带对抗 | 各自打各自的关卡副本，实时比分数/击杀数 | 无冲突（各答各的） | 低 |
| C. 答题接力 | 轮流答题主导权，非主导者看冷却 | 主导者答题决定全队加成 | 低 |

建议：**A + B 混合**——同一世界合作割草，结算时按个人输出分高下（既合作又攀比，最符合「小朋友一起玩」的场景）。

## 三、网络架构（推荐：Host-Authoritative + WebSocket）

```
[房主手机/PC 浏览器]                          [其他 1~3 名玩家浏览器]
  Phaser 客户端                                 Phaser 客户端
   ├─ 完整战斗模拟（权威）                        ├─ 输入采集（移动/攻击/答题选择）
   ├─ WS Server（ws 库，同一 JS 进程内）          └─ 渲染插值（15Hz 快照 → 60fps）
   └─ 15~20Hz 状态快照广播                        ↓ WS 上行输入 (~30Hz)
        ↑ 输入上行 (seq+dir+attack+answer)        ↓ 下行快照 (实体位置/HP/宝物/陷阱事件)
```

- **为什么 host-authoritative 而不是 lockstep**：割草是高实体数（≤45 只怪）实时对抗，
  确定性锁步对浮点/随机数要求苛刻（Math.random、Phaser tween 都不可重放）；权威主机 +
  状态同步 + 客户端插值是实现成本与体验的最佳平衡，且**答题判定天然在主机**，防作弊顺带解决。
- **服务器形态**：复用 Vite dev/preview 的 Node 进程起一个 `ws` WebSocket 服务
  （或独立 `server.cjs`，`node server.cjs --port 8090`）；房间 = 一个 WS 端口上的 room id。
- **发现房间**：M1 用「房主页面显示二维码/房间号 + IP」（浏览器无法 UDP 广播发现，
  二维码内容 = `http://<host-ip>:<port>/?room=xxx`）；M2 可加 mDNS（`bonjour` 依赖，需确认）。

## 四、协议草案（JSON over WS，后续可换二进制）

```ts
// C → H（玩家输入，30Hz，带序号做丢包补偿）
{ t: 'in', seq: 42, mx: 0.7, my: -0.2, atk: true, ans: 2, weapon: 1 }
// H → C（世界快照，15~20Hz，全量实体 + 增量事件）
{ t: 'snap', tick: 881,
  you: { id: 'p2', x: 1204, y: 610, hp: 87, weapon: 1, buffs: ['scholar'] },
  players: [...], monsters: [[id, x, y, hpRatio], ...],
  projectiles: [[x, y, angle], ...],
  events: [ { e: 'kill', id: 7 }, { e: 'chest', x, y }, { e: 'trapHit', p: 'p2', trap: 'poop' } ] }
// H → C（权威事件：答题浮层只出现在拾取者屏幕，结果广播）
{ t: 'quiz', to: 'p2', q: {...} }   // 拾宝者本地弹题
{ t: 'quizResult', p: 'p2', correct: true, buff: 'damage' }  // 全员飘字
// 房间控制
{ t: 'join', name: '小明' } / { t: 'start', level: 5 } / { t: 'result', ... }
```

- 帧率预算：4 人 × 45 怪 × 20Hz 快照 ≈ 40KB/s，局域网毫无压力；
- 位置同步用「主机发目标位置 + 客户端插值（lerp 100ms）」，不做客户端预测（M1 简化）。

## 七、风险与决策点

1. **依赖确认**：`ws`（M1 必须）+ 可选 `qrcode`（房主二维码，纯前端 canvas 生成可不加依赖——自绘 QR 太重，建议加依赖）。
2. **手机浏览器后台限流**：iOS Safari 切后台会断 WS——M2 的重连必须做，且答题浮层打开时禁止锁屏判定。
3. **难度平衡**：多人同世界怪物 HP 需按人数放大（bossHpPerPlayer），DDA 的 assist 按**全员最差表现**取值，防止一人躺平全员秒。
4. **存档/成就**：联机成绩只入「本局」，不写 progression 存档（防刷）；成就仅单机结算。
5. **家长监控冲突**：局域网联机不经过服务器，无数据出设备，隐私红线无冲突。

## 八、不做什么

- 不做公网匹配/账号系统（超出局域网范畴）；
- 不做帧同步回放/录像；
- 不改动单机模式的任何数值与验证门禁。
