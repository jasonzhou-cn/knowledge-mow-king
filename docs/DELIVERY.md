## 一、概述

这是一款「**答题 → 无双割草**」的休闲游戏 MVP。玩家先答对题目拿到加成，加成会直接强化**当前武器**；然后进入 60 秒生存关，用大刀 / 机关枪 / 霰弹枪抵挡从四面八方持续涌来的小怪，活到倒计时结束。

本作区别于普通割草游戏的根本在于 **GDD 1.3 的核心绑定**：答题质量（正确率 / 速度 / 连对）是决定割草爽感的唯一核心因素，答得越好，手上这把武器就越猛。

| 项目 | 数据 |
|---|---|
| 技术栈 | Phaser 3 + Vite + TypeScript |
| 逻辑分辨率 | 960 × 640（`src/main.ts`，Scale.FIT） |
| 代码规模 | 25 个 TypeScript 源文件，7968 行 |
| 配置数量 | 8 个 JSON |
| 外部素材 | **零**（全部程序化生成） |

## 二、已实现功能

### 2.1 完整核心循环（四场景）

| 场景 | 实现内容 |
|---|---|
| `MenuScene` | 关卡选择、开始游戏（支持空格 / 回车启动，左右键切关卡） |
| `QuestionScene` | 题目呈现、**两种选中方式**：① 直接点击移动中的答案卡片；② 停止按钮 / 空格 / 点击空白处停下，按重叠面积判定 |
| `GrassCuttingScene` | 60 秒倒计时生存，无双战斗主场景 |
| `ResultScene` | 成绩结算与展示 |

### 2.2 无双战斗系统

- **三把武器**：大刀 `blade`（近战扇形）、机关枪 `smg`（连发射击）、霰弹枪 `scatter`（扇形散射）
- **三种切换方式全部可用**：`1/2/3` 直接切、`Q/E` 循环切换、点击武器栏切换
- **攻击模型**：自动瞄准最近目标 + 手动触发（系统帮你锁定，出手由你决定）
- **走位**：键盘 WASD + 方向键；玩家位置有边界钳制（上边界额外留 64px 给 HUD）
- **武器栏 UI**：程序化武器图标 + 名称 + 快捷键 + 冷却进度条，当前武器金色描边高亮，切换带弹入动效

### 2.3 打击感三件套

- **顿帧 hitstop**：击杀瞬间把 `scene.time.timeScale` 压到 0.05
- **击杀特效**：爆散碎片 + 扩散圆环 + 白闪（纯 Sprite 池，`ParticleEmitter = 0`）
- **强化击退**：`killKnockbackMultiplier = 2.6`，击杀时把怪轰飞
- **反馈层**：伤害飘字 + 连击计数

### 2.4 怪物与难度曲线

- **持续涌怪**：从屏幕四边外围不断生成（非波次制），四面八方围攻
- **时间驱动难度**：`spawnInterval` / `batchSize` / `hpMultiplier` / `moveSpeedMultiplier` 四个维度随关卡时间线性插值
- **表现细节**：受击闪白、`dt` 化击退、尸体飞散（上限 12，FIFO 复用）、血量越低颜色越偏橙

### 2.5 答题 → 战斗绑定（本作核心）

- 答题质量决定加成强度，**加成只落到当前武器**上
- `durationMultiplier` 现作**冷却除数**使用：答得好 → 出手更快（HUD 文案已改为「攻速」）

### 2.6 工程架构

- **分层清晰**：`scenes/` 负责编排与生命周期，`systems/` 负责无状态游戏逻辑，`ui/` 负责展示与输入转发，`config/` 负责数据加载与校验
- **配置驱动**：四段式管线 `JSON → types → validator（手写，GDD 禁用 zod）→ resolve → ConfigLoader`，数值只存在于 JSON，代码不硬编码
- **零外部素材**：所有图形走 `Graphics → generateTexture`，所有音效用 WebAudio 程序化合成
- **性能红线（GDD 1.2）**：无物理引擎、无碰撞体、跳帧检测 + 距离平方比较、`ParticleEmitter = 0`、`camera.shake ≤ 0.006 / 160ms`

## 三、实测验证结论

> 以下均为**主理人独立复跑**的结果，不采信开发自报。

**静态与构建**
- `npx tsc --noEmit` → **0 error**
- `npm run build` → 32 modules transformed，gzip **371.95 kB**

**CDP 无头浏览器全流程试玩**
- 菜单 → 答题 → 割草 → 结算，**全流程通过**
- 控制台 **0 error**、**0 未捕获异常**
- 武器切换全通：`1/2/3` 直切、`Q` 回绕 `0→2→1→0`、`E` 回绕 `2→0→1→2`、点击武器栏生效
- 击杀确认生效：大刀 +9 / 机关枪 +16 / 霰弹 +10，连击峰值 300+
- **数据驱动验证**：把 `questionCount` 从 5 改成 1，答题次数从 11 降到 3 —— 证明配置真的在驱动行为，不是摆设
- **特效池不击穿**：45 怪同屏时碎片峰值 32/60、圆环 5/18、白闪 3/18，三类池 cap hits 全为 0

**难度曲线调参前后对比**（60 秒全程采样，每 2 秒一次）

| 指标 | 调参前 | 调参后 | 变化 |
|---|---|---|---|
| 撞满同屏上限时刻 | 39s | **56s** | 推迟 17s |
| 结束剩余 HP | 13 | **37** | 容错窗口 4s → 33s |
| 掉血速率 | 1.57 HP/s | **1.11 HP/s** | −29% |
| 前段 / 后段平均在场怪 | 24.0 / 58.7 | **14.7 / 37.5** | 比值 2.45 → 2.55 |
| 累计击杀 | 305 | 207 | −32% |

**调参的核心思路**：不是靠「后期刷更多怪」来制造压迫感，而是靠**击杀效率递减** —— 前段怪只有 3.2 血（一刀秒，砍得爽），后段 46 血（砍不动，自然堆积）。这一个改动同时解决了「前段砍空气」和「后段站桩割墙」两个问题。

## 五、已知短板

1. **武器栏点击热区外扩被屏幕底边吃掉 22px**
   声称向下外扩 32px，但格子底边在 y=630、屏幕高 640，实际只多出 10px 可点区域。要真正改善需把武器栏整体上移，会连带调整 HUD 间距。PC 端 66px 可点区域够用，故本次未动。

2. **「站桩割墙」缺乏正确的度量手段**
   目前用「后段击杀数 / 前段击杀数」比值近似，但这个指标会把「后段敌人本来就该更多」误判成缺陷（后段击杀多恰恰是设计意图）。真正该测的是「**玩家站桩不动 vs 主动走位的存活差异**」。

3. **`__KB_DEBUG__` 调试句柄仍挂在 `GrassCuttingScene.create()` 末尾**
   供无头浏览器读取运行时状态，是只读 getter，不驱动任何逻辑，可安全删除。建议保留到自动化测试体系建立后再清理。

4. **自动化测试覆盖不足**
   目前只有 `scripts/smoke-combat.ts` 和 8 个 CDP 验证脚本，没有单元测试。
